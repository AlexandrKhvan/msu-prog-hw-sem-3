## Тестовое окружение
- **Процессор:** AMD Ryzen 7 5825U (8 ядер, 16 потоков, базовая частота 2.0 ГГц, Boost до 4.5 ГГц)
- **Операционная система:** Linux (Ubuntu / WSL2)
- **Компилятор:** GCC (C11, флаги: `-Wall -Wextra -Werror -O2 -pthread`)


## 1. Сборка и запуск

Все действия выполняются через утилиту `make`:

```bash
# Сборка всех трех исполняемых файлов (task1, task2, task3)
make

# Запуск серии экспериментов и автоматическая генерация отчетов
make reports

# Очистка временных файлов, бинарников и отчетов
make clean
```

## 2. Что сохраняется автоматически

При запуске команды `make reports` (или при ручном старте каждого бинарника `./task1`, `./task2`, `./task3`) программы выполняют бенчмарки и самостоятельно формируют итоговые файлы отчетов с Markdown-таблицами:

1. **`report_task1.md`** (Задание 1: Параллельное умножение матриц):
   - Таблица сравнения классического алгоритма и метода с предварительным транспонированием $B^T$.
   - Замеры времени на $1, 2, 4, 8$ потоках для матриц $500\times500$, $1000\times1000$, $1500\times1500$.
   - Расчет коэффициента ускорения ($S = T_1 / T_P$) и статус проверки точности (`OK`).

2. **`report_task2.md`** (Задание 2: Внешняя многопоточная сортировка):
   - Таблица времени внешней сортировки больших объемов данных (от 2 до 16 млн чисел $int32$).
   - Разделение замеров на две стадии: параллельная сортировка блоков пулом потоков в ОЗУ (Фаза 1) и $K$-путевое слияние (Фаза 2: Min-Heap Merge).
   - Общее время работы, ускорение и статус верификации отсортированного файла.

3. **`report_task3.md`** (Задание 3: Параллельный поиск с координацией процессами):
   - Таблица скорости поиска подстроки пулом дочерних процессов ($1, 2, 4, 8$ воркеров) по набору файлов.
   - Фиксация времени до ранней остановки при достижении лимита совпадений $N$ ($10, 50, 200$).
   - Демонстрация самостоятельного прекращения поиска рабочими процессами через сигналы `SIGUSR1` и разделяемую память `mmap`.
